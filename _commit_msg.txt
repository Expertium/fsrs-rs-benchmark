iter19: build host batches once — +14.5% median, bit-for-bit (+ plot/README polish)

After the O(N) window collapsed the forward, the per-user SETUP floor grew to
~a third of the largest users' time. train() was handed weighted_train_set.clone()
plus weighted_train_set (train == test in BOTH compute_parameters() and benchmark()),
so it cloned the whole dataset AND ran build_host_batches() twice on identical data.
Now train() takes ONE dataset, builds the host batches ONCE, and validation reuses
them (only the index order differs: per-epoch reshuffle for the gradient vs the fixed
valid_order). Drops one O(N) clone + one full build_host_batches().

  * median speed_ratio 1.1455 (mean 1.1464); 47ms -> 40.5ms.
  * BIT-FOR-BIT: 0/50 param diff, d_AVG LogLoss 0.000000 (grad/valid only ever READ
    the immutable batches).
  * complexity 7207 -> 7204 (removed the test_set param + valid_host build + clone).

Re-anchor (overdue): the iter18 champion measured DIRECTLY against the iter-0 baseline
back-to-back is x62.04 median (mean x72.0), vs the product line's x65.5 — so the
compounding winner's-curse inflation is only ~5-6%. Cumulative accuracy cost is
+0.001087 log loss vs the original, inside the +-0.0015 band.
